# iOS and SwiftUI development from tandesk

Researched 2026-09-25. This is advice for the NixOS x86_64 workstation, not an installed setup.

## Practical answer

You can do useful Swift work on tandesk: write and test platform-independent Swift packages, app models, networking code, parsers, and other logic. Swift officially supports Linux and includes Swift Package Manager; `swift build` and `swift test` work for packages whose dependencies also support Linux. Swift.org offers Swiftly and official Linux containers, and SourceKit-LSP works with editors that support LSP. The official VS Code Swift extension adds completion, debugging, and tests for Swift packages. [Swift Linux installation](https://www.swift.org/install/linux/), [Swift getting started](https://www.swift.org/getting-started/), [Swift VS Code guide](https://www.swift.org/documentation/articles/getting-started-with-vscode-swift.html)

Native **SwiftUI/iOS app development still needs an Apple environment** for the UI loop. Apple presents SwiftUI as an Apple-platform framework, and Xcode on macOS supplies the iOS SDK, SwiftUI previews, Simulator, device tooling, and app build/submission workflow. A Linux Swift compiler does not turn a SwiftUI app target into a locally buildable or previewable target; that conclusion follows from the platform and toolchain requirements in Apple's docs. [SwiftUI](https://developer.apple.com/swiftui/), [Xcode](https://developer.apple.com/xcode/), [Xcode system requirements](https://developer.apple.com/xcode/system-requirements)

The recommended setup for regular SwiftUI work is a Mac running current Xcode, accessed from tandesk. Keep the app repository on the Mac and use a remote GUI session for Xcode's canvas, Simulator, and signing. Physical-device debugging also needs a supported connection between the Mac and the device. The installed Zed editor (`zeditor`) can open the Mac project over SSH. Zed supports macOS remote hosts and runs language servers, tasks, and terminals there; its Swift support uses SourceKit-LSP. Microsoft's VS Code Remote-SSH is another documented option, if that editor is preferred. Apple's Screen Sharing supports third-party VNC clients, so a separate GUI connection can show Xcode and Simulator on tandesk. [Zed remote development](https://zed.dev/docs/remote-development), [Zed Swift](https://zed.dev/docs/languages/swift), [VS Code Remote-SSH](https://code.visualstudio.com/docs/remote/ssh), [Apple screen sharing](https://support.apple.com/en-vn/guide/mac-help/mh11848/mac)

## Paths without a local Mac

- **iPad available:** Swift Playground on iPad can create, preview, and run SwiftUI iPhone/iPad app projects, use Swift packages, and submit eligible apps to App Store Connect. Apple says those projects can later open in Xcode on Mac. This option lets you start with real SwiftUI without access to a Mac. I recommend it for learning and smaller app projects. [Swift Playground](https://developer.apple.com/swift-playground/), [Swift Playgrounds documentation](https://developer.apple.com/documentation/swift-playgrounds)
- **Cloud CI available:** GitHub Actions has macOS runners with Xcode; these can build and test an existing project after each push. They are useful verification, but job logs and artifacts do not provide an interactive SwiftUI preview or Simulator workflow on tandesk. Xcode Cloud also builds/tests/archives, but Apple requires initial setup in Xcode and Apple Developer Program membership. [GitHub-hosted runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners), [Xcode Cloud setup](https://developer.apple.com/documentation/xcode/setting-up-your-project-to-use-xcode-cloud), [Xcode Cloud workflow actions](https://developer.apple.com/documentation/xcode/configuring-your-xcode-cloud-workflow-s-actions)
- **No Apple device or Mac:** Start a cross-platform Swift package on Linux and isolate UI-independent code there. You can learn Swift and implement/test much of an app's behavior, but must defer SwiftUI integration, iOS-specific APIs, previews, Simulator testing, and final app signing/builds to an Apple environment. [Swift Linux installation](https://www.swift.org/install/linux/), [Xcode](https://developer.apple.com/xcode/)

## Machine-specific notes

Read-only checks in this session found NixOS 26.11 x86_64 on `tandesk`; `swift`, `swiftc`, `sourcekit-lsp`, `code`, and `zed` were absent from `PATH`, while Zed is present as `zeditor`. This repo's pinned nixpkgs evaluates `pkgs.swift` and `pkgs.sourcekit-lsp` at Swift 5.10.1. Swift.org released 6.4 on 2026-09-15, and the official Swift image lists `6.4.0-noble`; a recent official toolchain in a container or supported Linux environment is preferable if parity with a current Mac toolchain matters. The `docker` command here uses a Podman compatibility layer and emitted a missing `/etc/subuid` warning, so container execution has not been validated. No Swift build, installation, or machine configuration change was made. [Swift 6.4 release](https://www.swift.org/blog/swift-6.4-released/), [official Swift image](https://hub.docker.com/_/swift)
